# 개발과 검증 기록

공개 독자가 개발자의 기여, 결정과 검증 근거를 빠르게 따라갈 수 있게 실제 작업 기록을 재구성한 문서다. 로컬 환경 정보를 익명화한 [개발 당시 상태 기록 보관본](Original/Status.md)에 일정, 실패, 수정, 재검증을 당시 기록 순서대로 보존했다. 아래의 날짜별 사례는 개발 이력이며, 현재 배포 상태는 [공개 스냅샷 검증](#공개-스냅샷-검증)에 정리했다.

## 게임과 구현

게임의 목표와 조작, 분신 재생·전투·성장 흐름은 [설계 문서](Design.md)에 정리했다. 개발자는 전투·난이도·검증 조건을 정하고 직접 C++을 작성하거나 플레이로 확인했다. Codex는 게임 기반 구현 지원, 코드·설계 리뷰, 검증 도구 작성과 결과 대조를 맡았다.

| 사례 | 개발자 기여 | Codex 지원과 확인 |
| --- | --- | --- |
| 분해장, 경로와 피격 표시 | 본체 전용 주기 피해, 분신별 경로 색·끝점, 피격 중 표시 전환 구현 | 분해장 반경 조정, [회귀 검사](../Source/EchoAssault/EchoGameplayTests.cpp#L543), 구현 검토 |
| 탄환 렌더링 | 메시·색별 ISM 그룹과 물리 Tick 이후 일괄 갱신 구현, Unreal Insights에서 구간 선택과 타이머 확인 | 동일 빌드 A/B 실험 구성, 트레이스 수집과 수치 재집계 |
| 강화창 입력 전환 | `FlushPressedKeys()` 호출로 눌림 상태를 정리하고 11/17에 W 누름·메뉴 진입·키 해제·복귀 절차를 직접 검증 | 입력 전환 흐름 리뷰와 빌드·검사. 11/19에 비슷한 증상이 한 차례 보고됐으며 당시 조건과 원인은 미확인 |

## 실패 분석과 재검증

| 당시 기록 | 실패에서 확인한 근거 | 수정과 재검증 |
| --- | --- | --- |
| 11/16 적 생성 충돌 | 사용자 로그에서 `SpawnEnemy`의 `Unit->bRanged` 접근 시 0x460 쓰기 오류를 확인했다. 생성 결과 유효성 검사가 빠져 있었다. | 생성 전후를 점검하고 등록 중 파괴된 적의 제외를 구현했다. 당시 `Timeline` 자동 검사는 통과했고 수정 직후의 플레이 재검증은 대기였다. |
| 11/17 충돌 회귀 검사 | 첫 보고서에서 `SpawnOverlap`과 `CurrentWorldCombat`가 실패했다. 등록된 구체의 충돌 형태와 엔진 프레임 경계가 검사 코드의 가정과 달랐다. | 테스트 구체의 반지름 갱신과 프레임 예약을 수정했다. 첫 재실행에서 `SpawnOverlap`이 통과했고, 이어 `Fixed-20261117-045327-431`에서 Unreal 검사 4/4가 통과했다. |

검사 보고서는 [CheckAutomationReport.ps1](../Tools/CheckAutomationReport.ps1)에서 판정하도록 모았다. 당시 실패 보고서에서는 실패 검사와 조건을 출력했고, 재실행에서는 새 보고서의 성공을 확인했다. 종료 코드 0만 나온 실행은 테스트 로그와 보고서 생성 여부까지 구분했다. [충돌·프레임 설계](Design.md#객체-수명과-충돌-검증)

## 강화 전후 분신 공격 회귀

개발자가 검토한 규칙은 과거 공격의 강화 단계가 현재 강화에 의해 바뀌지 않는다는 것이다. Codex는 [EchoGameplayTests.cpp](../Source/EchoAssault/EchoGameplayTests.cpp)의 `EchoAssault.Gameplay.WeaponUpgradeReplayBoundary`에 적용했다.

| 당시 플레이어 발사 | 첫 분신의 경계 | 그 시점까지 분신 탄환 검증 |
| --- | --- | --- |
| 10초, 칼날 1단계 | 18초 | 1단계 6발, 2단계 0발 |
| 13초, 칼날 2단계 | 21초 | 1단계 6발, 2단계 8발 |

슬롯 0은 플레이어, 슬롯 1은 첫 분신이다. 테스트는 지정된 슬롯의 탄환을 당시 단계별로 집계한다. 각 경계 직전과 두 번째 경계의 다음 프레임도 확인한다.

## 인수인계와 QA 사례

11/20에 개발자가 기존 대화를 전달하지 않은 새 Codex 세션에 시작 문서, 로컬 Git과 검사 자료를 줬다. 세션은 [PerfCheck.ps1](../Tools/PerfCheck.ps1)을 선택해 기록을 검토하고 실제 1080p 측정을 다시 실행했다. 재실행 `PerfCheck-20261120-010224-535`는 이동·정지 각각 3회 유효였다. 이후 개발자가 다른 새 세션에 저장소 QA 스킬을 지정하고 세 사례를 평가하도록 요청했다.

| 평가 상황 | 판정 근거 | 결과 |
| --- | --- | --- |
| 정상 측정 `004124-569` | 프레임 CSV의 뷰포트·실행별 저장 설정·회차 수 | 1080p 6회 유효 |
| 해상도 불일치 `221257` | 인자는 1920×1080, 저장 설정은 888×500, 실제 뷰포트 열 부재 | 1080p 비교 제외 |
| 스테이징 실패 `010148-557` | 평가 범위 내 최신 실행의 쓰기 권한 오류, 종료 코드 1, 캡처 0회 | 실패 기록과 이전 유효 결과를 구분 |

구성은 Codex가 작성한 스킬과 개발자가 지정한 사례 범위다. 세 판정은 원본 CSV·설정·실행 기록과 재대조해 3/3 일치를 확인했다. [QA 스킬](../.agents/skills/echo-performance-qa/SKILL.md) · [선별 근거](Evidence/QA-Case-Evidence.json)

## 성능 근거

- **1080p 전투 계측** · 개발자가 시작 적 500마리 중 원거리 적 100마리와 이동·정지 조건을 정했다. `PerfCheck-20261120-205404-312`에서 실제 1920×1080, 측정 전 세 분신의 공격 재생, 회당 1,800프레임을 대조해 6/6회가 유효했다. p95의 3회 중앙값은 이동 13.42 ms, 정지 13.57 ms다. [프레임 집계](Evidence/PerfCheck-Summary.json)
- **빌드 입력 해시** · 개발자가 코드·설정·맵과 에셋까지 포함할 범위를 정했다. Codex는 상대 경로와 파일 내용의 SHA-256을 패키징 전후에 비교했다. 위 실행에서 22개 파일이 일치했다. 이 비교와 실제 뷰포트·회차 유효성은 각각 판정한다. [입력 지문](Evidence/PerfCheck-BuildInputs.json)
- **ISM 격리 CPU 비교** · 개발자가 Unreal Insights에서 160발/초 트레이스 두 개의 360프레임 구간을 직접 확인했다. Codex가 재집계한 첫 쌍의 프레임당 좌표 적용 평균은 0.349 → 0.026 ms, 발사 준비와 월드 Tick을 포함한 구간은 2.534 → 2.216 ms다. 동일 빌드의 NullRHI CPU 구간을 비교한 수치다. [계측 범위와 샘플](Evidence/README.md#탄환-ism-격리-측정)

## 공개 스냅샷 검증

- **공개 소스** · 2026-11-21에 별도 복사본으로 Win64 Development Editor 빌드, 네이티브 리플레이 10개 조건, Unreal 자동 테스트 12개를 통과했다. Win64 Shipping 빌드·쿠킹·스테이징도 종료 코드 0을 기록했다. [검증 결과 발췌](Evidence/Snapshot-Verification.json)
- **Windows 배포** · 공개 Shipping ZIP을 새 폴더에 풀어 같은 PC에서 게임 창 1280×720과 정상 종료를 확인했다. GitHub에서 공개 다운로드 접근과 업로드한 ZIP의 SHA-256 일치도 확인했다. 이 실행 점검의 범위는 기동·종료이며 실제 조작 플레이와 타 PC 검증은 별도다. [Windows Shipping Release](https://github.com/tjwjdah/EchoAssault/releases/tag/portfolio-win64)
