# Echo Assault 설계

시간 잔상과 전투 구조를 빠르게 파악할 수 있도록 개발 당시의 설계 판단을 현재 구현과 함께 정리한 공개 문서다. 상세 결정과 당시 계획은 공개용 익명화 기준을 적용한 [개발 당시 설계 보관본](Original/Design.md)에서 볼 수 있다.

## 전투 흐름

WASD로 드론을 조종하고 마우스 방향으로 자동 사격한다. 경험치 결정을 모으면 플레이를 멈추고 강화 셋 중 하나를 선택한다. 3:30부터 최종 웨이브, 4:00에 승리, 체력이 0이면 패배다. 다시 시작하면 아레나를 다시 열어 시간 기록과 월드 객체를 초기화한다.

| 게임 시각 | 동시 생존 적 목표 |
| --- | ---: |
| 0:00–0:30 | 0 → 100 |
| 0:30–1:00 | 100 |
| 1:00–1:30 | 100 → 200 |
| 1:30–2:00 | 200 |
| 2:00–2:30 | 200 → 300 |
| 2:30–3:00 | 300 |
| 3:00–3:30 직전 | 300 → 400 |
| 3:30–4:00 직전 | 500 |

적 수는 동시 생존 목표다. 처치 후 부족한 만큼을 여러 프레임에 나눠 보충한다. 적끼리는 구체 충돌로 밀리며, 사방의 경계가 전장 밖으로 나가는 것을 막는다. 원거리 적은 탄환을 발사한다. [전투와 생성 코드](../Source/EchoAssault/EchoGame.cpp) · [적/탄환 Actor](../Source/EchoAssault/EchoActors.cpp)

## 시간 잔상

### 기록과 재생

1. `AEchoGame::Tick`은 공통 `FEchoHistory`에 프레임별 위치·조준각을 기록한다. `RecordWeapons`는 발사 시각·원점·방향·무기·당시 강화 단계를 `FEchoShot`에 저장하고 현재 공격도 실행한다.
2. `ReplayEchoes`는 분신별 `FEchoClock`을 전진시킨다. `PoseAt`은 이웃한 위치와 회전을 보간한다. `ReplayShotRange`는 직전 재생 시각보다 늦고 현재 재생 시각까지인 발사를 보관 순서대로 전달한다. 같은 시각의 발사도 모두 처리한다.
3. `Fire`는 기록된 공격을 현재 월드의 투사체로 생성한다. 당시 강화와 발사 조건을 보존하면서 현재 적에게 명중·피해·처치를 판정한다. 유도탄은 발사 후 현재 살아 있는 적을 탐색하고, 분해장은 플레이어 주변에서만 동작한다.

위치와 공격 이벤트를 분리해 각 분신에 별도의 재생 시각을 적용한다. 기록은 약 26초로 유지하고 1초마다 정리한다. 경계 앞 위치 샘플 하나를 남겨 보간이 끊기지 않게 하며, 정리와 조회 경계는 이진 탐색한다.

### 지연과 경로 표시

- 첫 분신은 8초 후 등장하고 최대 3기까지 늘어난다. 기본 지연 8·16·24초는 가속 강화로 7·15·23초, 이어 6·14·22초를 목표로 한다. 게임 시간 1초당 지연을 최대 0.25초 줄이고, 재생 시계가 지나간 공격 이벤트를 처리한다.
- 늦게 획득한 분신은 획득 시각에 해당하는 과거 지점에서 출발한다. 첫 재생 경계를 잡아 획득 전에 쌓인 공격이 한 번에 나가지 않도록 했다.
- HUD의 경로는 목표 지연값이 아니라 분신 시계가 실제로 진행한 구간에서 가져온다. 보간한 경계와 내부 위치 샘플을 유지하며, 개발자가 구현한 분신별 색상과 끝점으로 구간을 구분한다.

## 탄환 표시와 입력 전환

탄환의 이동·겹침·수명은 탄환 Actor에서 처리한다. `AIsmManager`는 메시와 색이 같은 탄환의 표시를 그룹화하고 물리 처리 후 `BatchUpdateInstancesTransforms`로 좌표를 넘긴다. 충돌 검사와 표시 갱신 비용을 따로 볼 수 있도록 Unreal Insights에서 같은 발사 조건의 개별 호출과 일괄 호출을 비교했다. [계측 범위](Evidence/README.md#탄환-ism-격리-측정)

강화창이 열릴 때 입력 모드가 바뀐다. 그 사이 놓친 키 해제가 이동 상태에 남을 수 있어 `FlushPressedKeys()`로 기존 눌림 상태를 정리한다. [입력 모드와 HUD](../Source/EchoAssault/EchoInterface.cpp)

## 객체 수명과 충돌 검증

`SpawnActorDeferred`로 적을 만든 뒤 반환값을 확인하고 체력·종류·공격 시각·외형을 설정한다. `FinishSpawning` 중 겹침 콜백이 객체를 파괴할 수 있어 등록 직후에도 생존 여부를 확인한다. 초기 크래시에서 확인한 것은 생성 결과 검사가 빠진 상태의 쓰기 오류였고, 당시 엔진 내부 원인은 미확정으로 기록했다.

엔진 동작을 사용하는 회귀 테스트도 등록 순서와 프레임 경계를 지켜야 했다.

| 확인한 문제 | 바꾼 검사 조건 |
| --- | --- |
| 테스트의 등록된 구체에서 `InitSphereRadius`로 값만 바뀌어 충돌 형태가 갱신되지 않았다. | 등록된 테스트 구체는 `SetSphereRadius`로 갱신한다. 게임 생성자의 등록 전 초기화는 유지했다. |
| 한 엔진 프레임에서 월드를 12회 갱신해도 `GFrameCounter` 중복 방지로 투사체는 1회 이동했다. | `QueueProjectileFrames`가 서로 다른 엔진 프레임에서 월드 Tick을 예약한다. 월드 수명은 공유 참조로, 프레임 사이에 파괴될 수 있는 적·탄환은 약한 참조로 관리한다. |

발사·겹침·피해는 실제 엔진 경로를 따라 검증한다. 화면의 Slate 입력, 아레나 재시작과 전투 조작감은 별도 플레이로 확인한다. [충돌 회귀 테스트](../Source/EchoAssault/EchoGameplayTests.cpp) · [실패와 재검증 기록](Status.md#실패-분석과-재검증)
