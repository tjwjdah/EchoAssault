## 확정된 범위

기울어진 3D 탑다운 카메라에서 WASD로 드론을 이동하고 마우스로 기본 블래스터를 조준한다. 무기는 자동으로 발사한다. 단일 아레나에서 적을 처치하고 경험치 결정체를 모아 무작위 강화 세 개 중 하나를 마우스로 선택한다. 210초부터 최종 웨이브, 240초에 승리, 체력 0에 패배한다. 종료 화면에서 같은 맵을 새로 연다.

| 범위 | 11월 19일 MVP | 11월 22일 최종 |
|---|---|---|
| 전투 | 블래스터, 추적형 적, 체력과 피해 | 유도탄·방사형 칼날, 원거리 적, 최종 웨이브 |
| 시간 잔상 | 8초 후 등장, 이동과 사격 재생, 현재 적에게 피해 | 16·24초 잔상 획득, 지연 2단계 강화, 제한적 줌 |
| 성장과 결과 | 경험치 수집, 정지·선택·재개, 승리·패배·재시작, HUD | 무기별 3단계, 밸런스·가독성 검증 |
| 제출 준비 | 플레이 기록과 기술 테스트 | Windows 배포 빌드, README, 1~2분 영상, 증거 기반 지원서 초안 |

영혼 흡수장, 공격력 전용 분신 강화, 화면 밖 표시, 고급 이펙트 및 추가 외형은 선택 기능이다. 20~21일은 확정된 최종 범위를 통합하고 테스트한다. 후보 비교, 기존 프로젝트 전수 검토, 선정 전 수정 대기는 종료된 절차다.

## 본편 적 등장 목표

기준은 게임 시간과 아레나 전체의 동시 생존 적 수다. 증가 구간은 시간에 비례해 목표를 올리고, 유지 구간은 처치로 생긴 빈자리를 보충한다.

| 게임 시간 | 동시 생존 적 목표 |
|---|---:|
| 0:00~0:30 | 0 → 100 |
| 0:30~1:00 | 100 유지 |
| 1:00~1:30 | 100 → 200 |
| 1:30~2:00 | 200 유지 |
| 2:00~2:30 | 200 → 300 |
| 2:30~3:00 | 300 유지 |
| 3:00~3:30 직전 | 300 → 400 |
| 3:30~4:00 직전 | 최종 웨이브 시작, 500을 목표로 보충 |

3:30에 목표가 500으로 바뀐다. 부족분을 여러 프레임에 나눠 생성하는 속도는 구현과 플레이 검증에서 정한다. 4:00에는 기존 승리 판정으로 전투가 끝난다.

적은 구체 충돌체로 서로 밀린다. 구체 충돌체는 무중력이며 XY 평면 조인트를 해제한 상태다. 탄환 명중은 기존 겹침 이벤트, 근접 적의 플레이어 피해는 기존 거리 판정으로 처리한다.

아레나 사방의 보이지 않는 충돌 경계는 적 구체에만 반응한다. 경계 안쪽 면을 적 반지름만큼 밖에 배치해 적 중심의 XY 이동 범위를 기존 아레나 범위에 맞춘다.

## 핵심 흐름

1. EchoGame.cpp의 MoveAndAim이 플레이어 입력과 카메라 광선을 받아 이동·조준을 갱신한다. 비행 높이의 평면과 광선이 만나는 지점을 기준으로 방향을 정한다. 평평하고 장애물 없는 맵이므로 XY 경계를 제한하고 UE sweep과 충돌 컴포넌트를 쓴다.
2. AEchoGame::Tick에서 위치와 조준각을 공통 FEchoHistory에 기록한다. RecordWeapons는 발사 시각·원점·방향·무기·당시 단계를 하나의 이벤트로 저장하고 Fire로 실탄을 생성한다. 시행 중 획득·강화 수치가 과거 공격을 바꾸지 않는다.
3. ReplayEchoes가 슬롯별 FEchoClock을 전진시킨다. FEchoHistory::PoseAt은 이웃한 위치를 보간하고 회전은 짧은 방향으로 보간한다. 발사는 EchoPlayback.h의 ReplayShotRange가 직전 시각보다 늦고 현재 시각까지인 모든 이벤트를 시간순으로 전달한다. 같은 시각의 두 발도 보관 순서대로 실행한다.
4. Fire는 동일한 이벤트에서 UE ProjectileMovement를 만든다. 블래스터는 당시 방향으로 날고, 유도탄은 당시 원점과 방향에서 출발해 현재 살아 있는 적을 찾는다. 목표 컴포넌트는 엔진의 약한 참조다. HitUnit이 현재 월드에 피해와 경험치 결정을 발생시킨다.
5. 레벨업은 월드 일시정지와 Slate 버튼으로 처리한다. 강화·결과창 진입 시 PlayerInput->FlushPressedKeys()로 기존 눌림 상태를 초기화한다(사용자 직접 구현). UI 전용 구간에서 놓친 키 해제가 게임 복귀 뒤 남지 않도록 엔진의 release·raw 값·플러시 처리를 사용하며, WASD 내부 bool만 직접 변경하는 방식은 사용하지 않는다. 마우스 선택을 기준으로 UIOnly 입력 모드를 적용하며 특정 위젯의 초기 키보드 포커스는 명시적으로 지정하지 않는다(사용자 선택). 버튼 자체의 포커스 기능을 모두 비활성화하는 것은 아니며 키보드 전용 탐색은 별도 보장하지 않는다. 선택 후 재개하면 게임 시계가 이어진다. Restart는 레벨을 다시 열어 GameMode, 기록, 적, 투사체, UI 수명을 함께 종료한다.
6. 분신이 따라올 경로는 공통 위치 기록에서 잘라 표시한다. 첫 분신의 경로는 첫 시계의 실제 재생 시각부터 현재까지이며 등장 전에는 확보된 구간을 보여준다. 추가 분신이 등장하면 해당 분신부터 바로 앞 분신까지의 시간 구간을 별도 색으로 표시한다(사용자 직접 구현). 가속 중에는 실제 시계 지연을 기준으로 경계가 움직인다. History.PathBetween은 보간한 양 끝과 원본 중간 샘플을 유지한다. 화면 투영 후 HUD보다 먼저 폭 3px의 반투명 띠와 오래된 끝에 5px 표시를 그린다. 첫째는 보라색, 둘째는 주황색, 셋째는 민트색이며 끝점도 같은 RGB를 사용한다. 띠의 알파는 각 구간에서 0.22→0.48, 끝점 알파는 0.65다. 반투명 띠는 SE_BLEND_Translucent 삼각형으로 그린다.

## 기획의 빈틈을 메운 구현 기본값

| 상황 | 이번에 적용한 값과 이유 | 확인할 장면 |
|---|---|---|
| 피격 표시 | 기존 0.85초 무적 동안 기체 메시를 0.1초마다 반전한다(사용자 직접 구현). 누적 시간에서 처리한 주기만 빼 초과분을 보존하고 무적 종료 시 표시·누적값을 초기화한다. 강화 선택 중에는 월드 시간과 깜빡임 상태가 멈추고 선택 후 남은 무적 시간 동안 이어진다(사용자 선택). 승패 진입 시 기체를 보이게 복구한다. 충돌·카메라·피해 규칙은 유지한다. | 짧은 피격, 피격 중 강화 선택·복귀, 무적 종료·패배 시 표시 복구 |
| 시간 가속 | 지연 8/16/24 → 7/15/23 → 6/14/22초. 게임 1초에 지연을 최대 0.25초 줄여 1초 변화에 4초가 걸린다. 통과한 이벤트를 모두 재생한다. | 두 차례 강화 후 이동과 연사 간격 |
| 분신을 뒤늦게 획득 | 획득 시점에 해당하는 과거 위치에서 시작한다. 그 시각 이전의 모든 총알이 한 프레임에 터지는 현상을 방지한다. 첫 분신의 최초 등장 시각은 8초로 유지한다. | 게임 30초 이후 두 번째 분신 선택 |
| 기록 수명 | 프레임 단위 샘플 + 26초 보관, 1초마다 정리. 경계 직전 위치 하나를 남겨 보간한다. 검색은 이진 탐색. 물리 재시뮬레이션이나 전체 월드 녹화가 필요하지 않다. | 24초 잔상, 30/60/144 FPS |
| 선택지 소진 | 분신 수, 시간 가속, 무기 단계가 상한에 도달하면 후보에서 제거한다. 체력과 이동속도만 남으면 두 능력치를 조금씩 올리는 복합 강화로 서로 다른 3개를 유지한다. | 후반 레벨업에서 실제 스탯 변경 |
| 카메라와 난이도 | 거리 1650~1980cm, 플레이어 중심. 무기 수치·적 등장 비율·체력·속도는 첫 플레이용 임시값이다. | 화면 밖 분신, 마우스 조준, 후반 체감 |
| 소유권 | 기록에 적 Actor를 넣지 않는다. EchoKills는 분신의 처치 수만 센다. 명중률·피해량·성능 개선 수치는 별도 측정이 필요하다. | 결과 HUD의 분신 처치 수 |

UE는 월드·충돌·투사체·유도·카메라·정지·테스트 실행을 담당한다. 게임 코드가 직접 관리하는 부분은 공유 시간축, 서로 다른 재생 시각, 과거 공격 스냅샷과 현재 피해 판정의 결합이다. 네트워크 전체를 재생하는 Unreal Replay와 목적이 다르다.

## 충돌 검사의 환경과 객체 수명

게임의 생성 순서는 `SpawnActorDeferred → 반환 유효성 확인 → 체력·종류·공격 시각·외형 설정 → FinishSpawning → 다시 유효성 확인 → 생존 객체만 등록`이다. FinishSpawning 중 기존 탄환과 겹쳐 적이 죽거나, 기존 적 위치에 새 탄환을 만들다가 탄환이 먼저 파괴될 수 있다. 따라서 생성 성공뿐 아니라 완료 후 생존도 검사한다. 최초 크래시의 엔진 내부 원인을 이 시나리오로 확정한 것은 아니다.

테스트도 엔진의 등록·프레임 규칙을 따라야 한다. EchoGameplayTests.cpp의 검사 환경에는 다음 두 가지 수정이 필요했다.

- `SpawnActorDeferred` 이후 네이티브 컴포넌트는 이미 등록돼 있다. 이때 `InitSphereRadius`는 반지름 값만 바꾸므로 충돌 형태 갱신이 필요한 테스트에는 `SetSphereRadius`를 쓴다. 생성자에서 등록 전 기본 크기를 설정하는 게임 코드의 InitSphereRadius는 유지한다.
- 동일 엔진 프레임 안에서 UWorld::Tick을 12번 호출해도 틱 함수의 GFrameCounter 중복 방지 때문에 투사체는 한 번만 이동했다. 실제 진단은 월드 시간 0.200초, 이동 15.5cm였다. 시속도 930cm/s의 1/60초 한 번 이동과 일치한다. QueueProjectileFrames는 FFunctionLatentCommand로 서로 다른 12개 엔진 프레임에 걸쳐 테스트 월드를 갱신한다. 실제 엔진 이동·겹침·피해 경로를 유지하고, 기대 피해량이나 사망 조건을 낮추지 않는다.

비동기 검사 동안 월드의 수명은 공유 참조로 유지하고, 프레임 사이에 파괴될 수 있는 적·탄환은 TWeakObjectPtr로 확인한다. 결과 검사는 호출이 끝난 시점이 아니라 대기한 프레임 처리 이후에 수행한다. Slate UI와 실제 맵 재시작은 별도의 플레이 확인 대상이다. 현재 검증 성공 여부와 로그는 Status에만 기록한다.

## 면접 설명 연습

“플레이어가 쏜 직후 무기를 강화하면 8초 뒤 잔상의 총알도 강해지나요?” 먼저 RecordWeapons의 FEchoShot.Rank 저장 시점과 Fire가 읽는 값을 확인한다. 이어서 반대로 바뀌는 값, 즉 현재 적의 생존 여부와 충돌 결과를 설명한다. 프로그래머가 직접 관찰한 장면과 테스트 범위를 구분해 기록한다.
